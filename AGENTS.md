# Idea Ledger workflow

- The conversation with the user is the working room for brainstorming, research, challenge, and judgment. The Idea Ledger is the durable memory of that work, not a replacement for the conversation.
- Preserve this loop: brainstorm in chat -> fan out focused research when useful -> attack the idea -> decide with the user -> update the canonical database and dossiers -> regenerate, validate, and redeploy the Ledger.
- Keep rejected ideas visible. Record why an idea died and what would change the decision so later work compounds instead of repeating.
- Keep the Now page centered on the database as a long-lived decision archive. Do not make a hackathon, mining round, or temporary shortlist the primary organizing concept.
